Data Format Explorers

One sensor reading, six formats, every byte clickable

01

Protocol Buffers

a field is a number
Tags and varints. Field numbers on the wire, names only in the .proto.
  • tag = (field_number << 3) | wire_type, bit by bit
  • reader schema: rename free, renumber or type change silent
  • 500 readings: delimited stream vs one big message
 02

Apache Avro

a field is a name, the schema ships with the data
No tags at all. Container file, single-object and Kafka framing side by side.
  • schema JSON readable in the hex dump
  • sync markers: start at byte N, resync, decode
  • resolution: reorder ok, rename BREAKS, alias fixes it
 03

Apache Parquet

transpose, encode, describe yourself, skip
A real Parquet file written in the browser: row groups, pages, dictionary, RLE, Thrift footer.
  • dictionary + RLE / bit-packing vs sort order
  • min/max statistics in the footer
  • query planner: bytes read vs bytes in the file
 04

Apache Iceberg

a table is files about files
A real table written in the browser: JSON metadata, Avro manifests, Parquet data files with field ids.
  • which format holds what, and why Avro is not where your rows are
  • rename, add, drop, widen: metadata only, matched by field id
  • a commit per minute: metadata outgrows the data
 05

Apache Arrow

same columns, opposite goal: cycles, not bytes
Validity bitmaps, offsets and values at computed addresses. A real IPC file, FlatBuffers metadata included.
  • read row i: a handful of loads, nulls cost full width
  • slices are (offset, length), 0 bytes copied
  • the file body is the memory layout, measured load times from bench/06
 06

Lance

rows by id: the unit you decode is the price
Random lookups replayed on the real 10M-row files from bench/05.
  • Parquet row group vs Lance mini-block chunk
  • 1000 rows: the Parquet file read ten times over
  • field ids: the number camp, and the size it costs
