Apache Iceberg Table Format

JSON, Avro and Parquet in one table, and what each of them is for

1The table on storage

A reader starts at the newest metadata.json, follows the current snapshot to its manifest list, the manifest list to the manifests, the manifests to the data files. Your rows exist only in Parquet. Avro holds the bookkeeping: which files belong to the table, their row counts, per-column min/max. JSON holds the table itself: schemas, snapshots, the pointer to the current manifest list.

Iceberg's schema evolution does not come from Avro. It comes from field ids (step 3), and works the same whether the data files are Parquet, ORC or Avro.

2File structure

Binary stream view

Click a file in step 1, then a byte. In a manifest, the ASCII column shows three schemas: Avro's own, the table schema and the partition spec. Further down, each data file's lower_bounds and upper_bounds: per-column min/max, keyed by field id. Manifests in this table are written uncompressed so you can read them; the growth model in step 4 is calibrated on deflate-compressed ones. In a data file, the footer carries a field_id per column.
